### 사이드바 광고 위치 정책 문제 발견

광고 가이드 문서(`Ads develop.md`, 출시 체크리스트)를 검토하는 과정에서 두 가지 제약을 확인했다.

**제약 1 - 스크롤 화면 전용**: 출시 체크리스트 "배너 광고 스크롤 화면만" 항목. 사이드바는 드로어(drawer) 형태로 스크롤 가능한 화면이 아니다.

**제약 2 - 뷰포트 전체 너비**: 가이드에서 배너 컨테이너 `width`는 항상 뷰포트 전체 너비와 동일해야 한다고 명시(`100%` = 화면 전체). 사이드바는 `max-w-xs`(최대 320px)로 제한된 패널이라 조건을 만족하지 못한다.

사이드바에 달면 안 되는 거 아니냐고 했더니 사용자가 굉장히 곤란해했다. 메인 발자국 화면 하단은 플러스 버튼이 차지하고 있고, 메인 캔버스 자체가 DOM 스크롤이 아닌 canvas 렌더링이라 "스크롤 화면"으로 볼 수 없다. 현실적인 대안은 LogsPage(기록 모아보기) 스크롤 목록 하단이다.

다만 이 시점에 기획을 뒤엎기가 싫다는 의견이 있어서, 일단 사이드바에 달아둔 채 심사에 제출해보기로 결정. 통과하면 유지, 반려되면 LogsPage로 이동한다. 결과가 나올 때까지는 백로그로 관리.

### GPS 동의 UX 개편

지난 세션에서 발견한 두 가지 HIGH 이슈를 수정했다.

**이슈 1 — GPS 거부 시 consent 미저장**: "허용 안 할게요" 버튼 핸들러에 `localStorage.setItem('gps-consent', 'false')`가 없어서 팝업이 반복됐다. 근데 여기서 방향 논의가 생겼다. "GPS 없으면 이 앱 못 쓰는 거라 팝업 반복이 맞는 거 아니냐"는 얘기가 나왔고, 실제로 코드엔 모의 주소 폴백이 있었다. 이게 "GPS 필수" 의도와 안 맞는 어중간한 상태였다.

결론: GPS를 앱의 필수 조건으로 확정. 거부 버튼 자체를 없애고, 그 자리에 3줄 안내 메시지로 대체했다 — (1) 앱 사용에 위치 권한 필수, (2) 데이터는 기기에만 저장, (3) 원하지 않으면 앱 닫으라는 안내. `AlertDialog`, `TextButton` import도 함께 제거.

이 과정에서 `MOCK_ADDRESSES` 상수도 더 이상 쓰이지 않아 삭제했다.

**이슈 2 — reverseGeocode 타임아웃**: fetch에 `AbortController` + `setTimeout(5000)`을 추가해서 5초 안에 응답 없으면 강제 취소되도록 했다. 그런데 타임아웃 시 모의 주소로 폴백하는 건 의미 없다는 지적이 나왔다. GPS로 찍는 게 의미 있는 거지, 엉뚱한 주소 붙이는 건 아니라는 거다.

대안으로 "좌표만 저장해두고 나중에 주소 재시도" 방식을 채택했다. 구체적으로:
- `appendFootprint`에 `lat`, `lon` 파라미터 추가, 발자국 객체에 좌표 저장
- geocode 실패 시 `address: null`로 저장
- 팝업에서 address 없으면 "위치 확인 중..." 표시
- 앱 마운트 시(`[]`) `lat`/`lon`은 있고 `address`가 없는 발자국들을 자동으로 재시도

의존성 배열을 처음엔 `[date]`로 잡았다가, 같은 날짜에서 앱을 껐다 켜면 date 값이 안 바뀌어서 재시도가 트리거 안 된다는 걸 발견하고 `[]`로 수정했다.
