### 상단 레이아웃 균형 문제

다른 사용자 기기에서 찍은 스크린샷 두 장을 비교하다가 문제를 발견했다. 햄버거 버튼(`fixed top-4 left-4`)과 날짜 pill(`fixed top-0 pt-4`)이 각자 독립적으로 `fixed` 포지셔닝되어 있어서, 기기마다 수직 정렬이 미묘하게 달라 보였다. 이론상 같은 `top: 16px`이어도 각 요소의 높이 기준점이 달라 시각적으로 어긋나 보이는 것.

해결 방향은 두 요소를 같은 flex 컨테이너 안에 넣는 것이었다. 헤더를 `flex items-center justify-between`으로 바꾸고 `[햄버거 | 날짜 pill | 빈 spacer(w-10)]` 3열 구조로 재구성했다. 이렇게 하면 `items-center`가 항상 수직 중앙 정렬을 보장한다. 동시에 날씨 패널이 `top-24`(96px)로 너무 멀었던 것도 `top-[72px]`로 헤더 바로 아래로 당겼다.

### 상세 주소 표시 기능

"집에 있는데 고깃집 갔는데도 구분이 안 간다"는 피드백에서 시작됐다. 현재 `reverseGeocode`가 도로명 수준까지만 반환하다 보니 같은 도로의 다른 건물이 구분 안 되는 것.

건물번호(`house_number`)를 포함하는 상세 주소 모드를 설정으로 켤 수 있게 만들었다.

`reverseGeocode`가 기존에 `string`을 반환하던 것을 `{ simple, detail }` 객체로 바꿨다. `detail`은 `simple`에 `house_number`를 붙인 형태. 캐시도 동일 구조로 변경. 발자국 객체에 `addressDetail` 필드를 추가해서 두 버전을 모두 저장하도록 했다.

설정 값은 `localStorage('fp-address-detail')`로 저장. 상세 주소가 ON으로 켜지면 `addressDetail`이 없는 기존 발자국들도 자동 재지오코딩하는 `useEffect`를 추가했다.

### 주소 파싱 구조 개선

"김해시라고만 뜬다"는 피드백이 추가로 들어왔다. 원인을 추적해보니 기존 코드에서 `suburb`(동 이름)을 road의 폴백으로 쓰고 있었던 것이 문제였다.

```
// 기존: suburb를 road 대체재로 사용
const road = a.road || a.pedestrian || a.suburb || a.neighbourhood || '';
const district = a.city_district || a.borough || a.town || a.village || '';
```

김해시처럼 `city_district`가 없는 도시에서는 `district`가 비어버리고, `road`가 있으면 "삼안로"만, `road`도 없으면 "김해시"만 떴다. `suburb`(삼안동)가 road 자리를 잡으면서 구역 정보가 날아간 것.

`road`와 `area`를 완전히 분리해서 재구성했다:

- `road`: `a.road || a.pedestrian` (실제 도로명만)
- `area`: `a.suburb || a.quarter || a.neighbourhood || ... || a.village` (구역 정보)
- 조합 우선순위: `area + road` → `city + road` → `city + area` → `city`

이렇게 하면 "삼안동 삼안로"처럼 구역+도로가 같이 나온다. "김해시만 뜨는" 케이스는 OSM 데이터 자체가 없는 거라 코드로는 한계가 있다는 것도 확인했다. 주소 별명 기능(특정 좌표에 커스텀 이름 등록)이 근본적인 해결책이 될 수 있어서 백로그에 추가했다.

### 설정 페이지 분리

상세 주소 토글을 처음에는 사이드바 안에 직접 넣었는데, 설정이 늘어날 것을 고려해 별도 페이지로 분리하기로 했다.

`SettingsPage.jsx`를 `FeedbackPage.jsx`와 동일한 슬라이드 페이지 패턴으로 만들었다. `Sidebar.jsx`에서는 인라인 토글을 제거하고 "설정" 메뉴 항목(Settings 아이콘)으로 교체. `Footprint.jsx`에서 `currentPage`에 `'settings'` 케이스 추가해서 연결했다.
